## 窗口寄宿的已知限制（0.5.0 / T-131，能力边界，按设计 §0.1 记账）

1. **状态不记忆**（决策 3）：重启后回到监控模式，不恢复上次寄宿的窗口。
   - 为什么：HWND 跨重启失效，要以 `processPath + className` 指纹重匹配，收益/成本比低。
   - 副作用：`uiLayout.embedWidth / embedSource` 仍持久化，所以重启后会得到「宽度/选择
     都对、但处于监控模式」的面板——这是有意为之，不是 bug。
2. **跨屏 DPI 不重建容器**：容器在 attach 时按目标的感知上下文创建；把 ttFolio 拖到
   另一缩放比的屏幕后，容器不重建（矩形会跟着重算，尺寸正确、不越界，但老式
   System/Unaware 目标可能偏糊）。
   - 补法（未做，Phase 2）：`display-metrics-changed` 时若 `GetDpiForWindow(容器)` 与
     目标不一致则 detach + 重新 attach（会闪一下，需与用户确认优先级）。
3. **poster 是 attach 时刻的静帧**：浮层打开期间显示的是「最后一次看到的画面」，不刷新。
   - 为什么：窗口被重挂后 `EnumWindows` 枚举不到它，desktopCapturer 只能返回 null（实测）。
   - 替代：浮层收起立即恢复实时；无静帧时显示「浮层打开中，寄宿画面暂隐」占位。
4. **焦点提示是 1s 粒度**（主进程轮询 `IsWindow` + 焦点），不是实时事件。
   - 为什么：不装全局钩子（红线），子窗口焦点变化没有可订阅的跨进程通知。
5. **Alt+F4 保留系统语义**（决策 7）：会关掉被嵌程序本身；**硬崩溃连带**（决策 5）：
   宿主被强杀/断电时被嵌程序一起消失。Phase 3 独立宿主进程是可选根治，默认不做。
6. **结构性不支持**：WinUI3（Win11 记事本、Windows Terminal）、UWP/MSIX（计算器/设置）
   ——入口处如实拒绝并回落监控，不静默失败。**管理员窗口**自 0.5.2 起有显式出路：接管失败时
   可点「以管理员身份重启后再试」，代价（全应用提权 / 拖拽登记失效 / 每次启动弹 UAC）
   在确认框里逐条列出，默认不启用。
   - 未覆盖：该提权链路（UAC 授权 → 新实例自动开面板 → 进寄宿模式）尚未在真机跑通过一次，
     本机无法在不弹 UAC 的前提下验证；首次用户实操时若失败，优先查
     `--ttfolio-embed-retry` 是否到达（单实例锁已跳过）、面板是否收到 `tt:embed-retry`。
7. **被嵌程序自己的弹出窗口会「逃出」面板**：它自己 new 的顶层对话框/右键菜单不属于
   容器子树，会以独立窗口出现在面板外（Chromium 系程序的右键菜单同理）。这是
   `SetParent` 路线的固有行为，不做拦截。
8. **多槽标签页未做**（Phase 2）：当前是单槽，切窗口即替换。
9. **任务栏按钮归在 ttFolio 的进程分组下**（0.5.1 起有独立按钮）：悬停显示的是被嵌窗口的
   标题与实时缩略图，点它能把面板带回前台；但按钮的分组名/图标仍是 ttFolio 进程的。
   - 为什么：容器属于 ttFolio 进程，Windows 按进程/AppID 分组。想让按钮直接挂到 Chrome
     名下需要用 `IPropertyStore::GetValue` 抄对方的 AppUserModelID——koffi 读 `PROPVARIANT`
     指针会打崩主进程（实测），故不做。
   - 后续：等 koffi 有稳妥的 PROPVARIANT 读取方式，或改 C++ addon 时再补。
10. **接管最大化窗口时会先把它还原**（0.5.1）：视觉上能看到窗口从最大化变回浮动窗口再嵌进
    面板；分离时按原状态最大化回去。
    - 为什么：最大化状态下的窗口直接重挂会让 Chromium 合成输出失效（黑/白屏），必须先还原。
    - 后续：若要视觉无缝，需要在接管前先截图做过渡（成本高、收益低，暂不做）。

## 功能级（有最小可用实现，体验打折）

1. **文件移动/复制的长任务进度条**（FR-4.7 部分）——✅ **已补齐（0.4.3 / 第 61 轮）**
   - 原缺：fs/move 同步执行，无进度无取消；overwrite 在 schema 合法但无语义。
   - 补法（已实现）：tasks.start 异步任务化（kind 'move-copy'），状态栏全任务
     进度 + 按 taskId 精确取消；同盘 rename 瞬时、跨盘渐进复制→校验→删源
     （verify 全过才删源、取消绝不删源）；overwrite=先删目标旧内容（弹窗三选：
     覆盖/跳过/逐次询问）；单项失败不中止整批（部分成功标注）。
   - 回归锚点：fstask.test.ts 14 条（取消不删源/半成品清理/部分成功/HTTP 语义）。

2. **树节点右键菜单**（FR-2.10 的文件树部分）——✅ **已补齐（0.2.11）**

     并实装 F2/Delete 快捷键（此前快捷键帮助文案有承诺无实现）。
   - 本项从缺口清单闭合；右键菜单交互收敛见第 31 轮台账。

9. **集合手动排序**（0.2.11 新增缺口）——✅ **已补齐（0.3.8）**

   - 补法（已实现）：POST /api/collections/reorder 按传入顺序单事务全量重排；
     侧栏集合右键菜单「上移/下移」（首末项禁用），与相邻集合交换后全量重排。

10. **GitHub Token 明文存储**（0.2.12 有意取舍，2026-10-08 入册）
    - 现状：settings.github_token 为 SQLite 明文，未用 Windows 凭据管理器（DPAPI）。
    - 为什么现在不做：本地单机单用户威胁模型下，能读 `%APPDATA%\ttFolio\` 的人
      已拥有同级别系统访问权，Token 明文不构成额外暴露面；引入 keytar/DPAPI
      增加原生依赖与打包复杂度，收益不成比例。
    - 补法（若仓库转公开或引入多用户）：凭据迁入系统凭据管理器，settings 只留
      「已配置」标记；届时需一次性迁移旧值。

11. **titleBarOverlay 窗控区的能力边界**（第 89 轮入册，0.5.6 预定）
    - 现状：窗口 `titleBarStyle:'hidden'` + `titleBarOverlay`，原生 ─□× 由 OS 画在
      顶栏行内，底色/符号色随主题经 `tt:theme-changed` 上报同步。
    - 边界 ①：**非浅色主题启动首帧有色差**——构造时 overlay 是浅色默认底，渲染层
      主题解析上报前（约数百毫秒）深色用户会看到浅色窗控条。主进程不读主题
      （服务端 bundle 是副作用 IIFE 无导出，主进程无法直接取设置），首帧零闪
      需主进程预读设置，收益/成本比低暂不做。
    - 边界 ②：**窗控区恒实色**——OS 只收不透明 hex，玻璃主题下该条带不参与
      玻璃化（取渐变底近似实色 #e7eafa）。
    - 补法（若要做）：①主进程 boot 后建窗前经 `<dataDir>/token` + GET /api/settings
      预取主题定构造色；②无解（OS 限制），除非自绘窗控（会失去原生 Snap 布局、
      悬停预览等系统行为，不做）。

## 明确不做（范围外，仅留扩展位——与 C-56..C-62 对应，不是缺口）

- Git push/pull/fetch/远程/凭据；多用户登录权限；目录自动扫描；架构图生成/调 AI；
  IDE 能力（编译/调试/语言服务/搜索替换/内嵌终端）；任务协作体系；云同步多端。
- 预留位已就位：owner_id/actor 字段、collections 成员与 {paths} 占位符、core/terminal/ 目录、
  core/scanner.ts 接口签名、settings 的 scan_root_dirs 字段。
- **界面国际化**（2026-10-08 入册）：界面中文硬编码是当前产品定位（个人工作台）
  的有意决策，README 已双语；未来若面向国际用户再引入 i18n 框架整体替换。

## 环境限制（非代码缺口）

- Playwright Chromium 首次运行需下载浏览器；下载失败时 verify 会将 e2e 记 SKIP 并说明（默认决策 8）。
- PowerShell 文件夹对话框弹窗可能被系统策略拦截；此时用"粘贴路径"入口（三种入口互为备份）。
- **e2e 为冻结资产**（2026-10-08 入册）：tests/e2e 三份 spec 因「不跑 e2e」的既定政策
  长期未运行，选择器已随三十余轮 UI 演进漂移，当前视为不可直接执行的冻结资产；
  解冻前置条件＝运行并修复选择器或按现状重写，建议安排在 1.0 之前的整备轮。
