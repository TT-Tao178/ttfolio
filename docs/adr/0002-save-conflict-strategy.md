# ADR-0002 保存冲突策略：三元组校验 + 原子替换 + 草稿兜底

日期：2026-09-21 ｜ 状态：已采纳

## 背景
外部编辑器与 ttFolio 同时打开同一文件是常态。任何静默覆盖都是数据事故；任何"半个文件"都是元约束 M-1 的失败。

## 备选方案
1. 最后写入获胜（VS Code 默认）—— 静默丢字，否决。
2. 文件加锁 —— 无法约束外部程序，伪安全，否决。
3. 打开时记基线，保存前校验，冲突交用户三选一（采纳）。

## 决定
- 基线 = {mtime, size, sha256}；>5MB 只记 mtime+size 并标注。
- 保存链路：校验基线 → 不一致返回 409 MTIME_CONFLICT（附磁盘版本摘要与内容，供对比）→ 用户选 对比/覆盖(force)/放弃本地。
- 写入 = 同目录临时文件 + fsync + rename（同盘原子）；失败清理临时文件，原文件不受影响。
- 草稿独立于保存链路：1s 防抖写库 editor_drafts（UNIQUE(scope,path_key)），崩溃/强杀/刷新后恢复；冲突解决前草稿不删。
- 编码（UTF-8/BOM/UTF-16LE·BE/GBK）与换行（CRLF/LF/MIXED）探测后原样写回；只读文件明确报错，绝不改权限。

## 后果
- 正面：红线 4（永不丢字）有双重保障；冲突由用户裁决，符合 M-3 不静默。
- 代价：hash 校验对大文件有成本（分块 sha256，1MB 内毫秒级）；可接受。
