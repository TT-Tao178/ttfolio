# ADR-0001 PathGuard：所有文件操作的唯一路径关口

日期：2026-09-21 ｜ 状态：已采纳

## 背景
ttFolio 要在用户磁盘上活动，最致命的风险是把文件写到登记目录之外（路径穿越、符号链接逃逸、UNC/ADS、
Windows 保留名）。校验逻辑一旦散落各处，必然出现旁路。

## 备选方案
1. 各路由自行校验 —— 实现简单但必然漏（否决）。
2. chroot 式进程隔离 —— 与"单进程本地工具"形态不匹配（否决）。
3. 唯一关口模块 + 机械检查兜底（采纳）。

## 决定
- 所有用户文件读写必须经 `core/pathGuard.ts`：`resolve → 拒绝保留名/ADS/UNC/尾随点空格 → realpath → path.relative 判包含`。
- 白名单精确到"该项目目录 + 该项目文档挂载 + 该项目架构图目录"，无全局兜底根。
- 禁用字符串 startsWith 判包含（防 C:\a 与 C:\ab 误判）；ESLint no-restricted-syntax + verify.mjs 机械检查双重拦截。
- 新建场景（目标不存在）：逐级向上找真实存在祖先做 realpath，祖先必须落在白名单内且剩余相对段无 `..`。

## 后果
- 正面：越界面收敛到一个可测试的纯函数；pathGuard.test.ts 覆盖 ..、绝对路径、符号链接、保留名、ADS、UNC。
- 代价：所有文件操作都要带上下文（projectId → roots），路由层多一次查询；可接受。
